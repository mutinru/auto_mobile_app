# CLAUDE.md

Guidance for Claude Code when working in this repository.

**Факты о приложении — в `README.md`**: запуск, адрес бекенда, демо-аккаунты,
структура `lib/`, доменная модель, схема навигации, известные ограничения.
Прочитай его первым. Здесь — правила работы и места, где легко сломать что-то
молча.

## Границы репозитория

Это Flutter-клиент. **Бекенд — отдельный приватный репозиторий** (Laravel 13,
JSON API, Sanctum). Его кода здесь нет; если задача упирается в поведение API,
скажи об этом, а не выдумывай эндпоинт.

`design/` — статичные HTML-макеты, **источник правды по дизайну**. Экраны, цвета
(`lib/theme/app_colors.dart`) и шрифты перенесены оттуда, схема кузова в
`lib/widgets/car_schematic.dart` — пути из макета один в один. **Загляни в макет
прежде чем придумывать вёрстку**; что из них реализовано, а что нет — в
`design/README.md`.

Комментарии в коде и строки для пользователя — **на русском**.

## Рабочий процесс

```bash
flutter analyze
flutter test                   # suites на мок-репозиториях, бекенд не нужен
flutter run -d emulator-5554
```

`test/integration/` помечены тегом `integration` и в обычном `flutter test`
пропускаются (`dart_test.yaml`) — прогон должен быть полностью зелёным. Против
поднятого засиданного бекенда: `flutter test --run-skipped -t integration`.
Без `--flavor` `ApiConfig` берёт dev (в релизной сборке — prod). Тест, который
правит данные, всё равно проверяет `ApiConfig.isDev` и отказывается работать
с prod (образец — `api_repository_test.dart`). Осмотр он находит через `/orders/assigned`, а не по
номеру, и возвращает правки назад.

`adb` **не в PATH**, он лежит в `/android/SDK/platform-tools/adb` (путь к SDK
прописан в `~/.config/flutter/settings`):

```bash
ADB=/android/SDK/platform-tools/adb
$ADB -s emulator-5554 shell input tap <x> <y>
$ADB -s emulator-5554 exec-out screencap -p > shot.png
```

Координаты тапов — **в пикселях устройства** (1080×2400 на этом эмуляторе), а не
в масштабе картинки, которую читаешь обратно. Скриншоты проверки клади в
`screenshots/` (папка под игнором, в коммит не уедет).

Не коммить и не пушить без явной просьбы.

## Инварианты — сломать легко, заметить трудно

1. **Статус детали вычисляется, а не хранится.** Правда — только
   `InspectionPanel.condition` (A/B/C/D), `PanelStatus` выводится из неё
   (`lib/models/panel_condition.dart`, `panel_status.dart`). Стор **никогда** не
   пересчитывает статус локально: мутация возвращает с сервера деталь целиком,
   стор подменяет её в списке. Локальный пересчёт разойдётся с сервером.
2. **Детали адресуются стабильным кодом, а не id.** `InspectionPanel.id` — это
   `front_bumper`, `hood`, … из `BodyPanelType.code` на бекенде, а не число.
3. **Рейтинг исполнителя, срывы и `canReview` считает сервер.** Мутация отзыва
   возвращает заказ целиком — подменяй его, а не пересчитывай среднее или
   счётчики локально (как и статус детали). `UserSummary.missedOrdersCount`
   == null значит «этому зрителю не положено» (не заказчик) — не подставляй 0.
4. **Энамы Dart и PHP — ручные зеркала.** Пара живёт в репозитории бекенда
   (`CodeChannel` ↔ `App\Sms\CodeChannel`, остальные ↔ `App\Enums\*`, в том
   числе `ConversationType` и `ChatRole` чата, `NotificationType` ленты и
   `VinKind`).
   Меняя энам здесь, скажи пользователю: парная правка сама себя не сделает.

## Ловушки

README перечисляет ограничения приложения; здесь — что с ними делать.

- **`ApiInspectionRepository` требует `inspectionId`** — бери его у кандидата
  заказа (`OrderCar.inspectionId`). Не возвращай значение по умолчанию: раньше
  забытый id молча уводил на осмотр №1, чужой.
- **Кандидат подбора приходит с осмотром.** `addCar` — один запрос: сервер
  создаёт машину и осмотр вместе, у ответа уже есть `inspectionId`, и
  карточка сразу открывает осмотр. `startInspection` — только разовый
  осмотр (VIN и пробег обязательны); у подбора сервер ответит 422. Не
  возвращай второй вызов: сбой между ними оставлял кандидата без осмотра.
- **Без `finally` экран виснет на спиннере.** Добавляя загрузку, сразу пиши
  `try/catch/finally`, текст через `apiErrorText` и блок ошибки с «Повторить» —
  образцы: `OrderStore.loadAvailableOrders()`, `OrderDetailScreen._load()`.
  `InspectionStore.load()` ошибку не пробрасывает, а кладёт в `loadError`:
  экраны осмотра обязаны рисовать именно его, `catch` вокруг `load()`
  бесполезен (гейт на `car == null` оставит спиннер).
- **В сеть — только через `HttpTransport`** (`lib/data/http_transport.dart`):
  там таймауты (30 с, загрузки — 3 мин), без них на плохой сети спиннер висел
  бесконечно. Не зови `http.get/post/…`, `http.Client()` и `.send()` в обход —
  это ловит `test/http_transport_test.dart`. Запросы к API — через `ApiClient`
  (`get/post/patch/delete`, файлы — `multipart`); транспорт напрямую — только у
  `AuthService` (от него зависит сам клиент) и гостевой витрины.
- **401 — только через `AuthService.expireSession()`.** `ApiClient` делает это
  сам (`ApiClient.failure`, в том числе у загрузок). Запрос мимо `ApiClient`
  (только `AuthService`) обязан на 401 звать `expireSession()` — иначе
  протухшая сессия снова станет тупиком. Уводит на вход корень (`_RootGateState._onAuthChanged`), не
  экран. И наоборот: **стирать сессию — только на 401**. Нет сети, таймаут или
  5xx — не повод (502 во время выкатки разлогинил бы всех).
- **Вошёл — не значит есть `auth.user`.** После офлайн-старта токен есть, а
  профиля нет, пока `ApiClient` не догрузит его через `ensureUser()`. Читай
  `auth.user?.id`, не `auth.user!`; запрос мимо `ApiClient` профиль не поднимет.
- **Мок-репозиторий — общая фикстура всех виджет-тестов.** Новая запись в
  `MockOrderRepository._seed()` двигает вёрстку и ломает чужие `find.text` в
  соседних suites. Правя `_seed()`, прогоняй `flutter test` целиком, а не одну
  свою suite.
- **Ошибки запросов — через `widgets/api_error.dart`**: `showApiError(context, e)`
  (SnackBar) или `apiErrorText(e)` (строка в форме). Не печатай `'$e'` — это
  сырой `ApiException(422): {json}`. Ошибки 422 по полям —
  `ApiException.fieldErrors` (образец — `RespondSheet`, `payout_sheet.dart`).
  Сбой не запроса (распознавание VIN) — свой текст, не
  `apiErrorText`.
- **Непрочитанные поддержки — только с сервера** (`SupportUnread.refresh`),
  локально не уменьшай: чат сам отмечает прочитанное, а при его закрытии
  счётчик переспрашивает сервер. Новый вход в чат поддержки оборачивай в
  `SupportUnreadBadge`, иначе ответ оператора там не будет виден. Новый
  `ChatStore` открывай как `_openChat` в `support_sheet.dart` — с
  `unread.chatOpen`.
- **Непрочитанные уведомления — тоже только с сервера.** `NotificationStore`
  подменяет уведомление ответом `markRead` и отдаёт число в бейдж через
  `PolledUnread.report()`; не вычитай локально. Новый раздел с шапкой — добавь
  `NotificationBell` рядом с профилем, ленту открывай `openNotifications()`
  (репозиторий берётся из scope до маршрута, а не в builder).
- **Firebase — только через `PushService`/`PushMessaging`** (`lib/push/`), не
  зови `FirebaseMessaging` из экранов: в тестах Firebase нет, а сбой
  инициализации должен лишь выключать пуши. Тап по пушу не открывает экран из
  обработчика FCM — он становится `PushTarget` и уходит в `_RootGate._openPush`.
  Новый тип пуша — разбор в `PushTarget.fromData` и ветка там же.
- **Фото чата — только с `ChatRepository.imageHeaders`.** Они на приватном
  диске: `Image.network(url)` без Bearer получит 401 и молча нарисует заглушку.
  Адрес бери из `ChatAttachment.url` (уже переписан на `ApiConfig.origin`), а не
  из сырого JSON.
- **`InspectionStore(readOnly: true)`** — осмотр только для просмотра (заказчик
  подбора). Экраны осмотра гасят мутации по `store.readOnly`; добавляя новую
  мутацию, проверь этот флаг, иначе сервер ответит 403.
- **Голосовая заметка — `InspectionPanel.audioNoteUrl`, подписанная ссылка**:
  Bearer не нужен, но она живёт около часа. Не кешируй деталь дольше — после
  истечения перезагружай осмотр. Плеер и рекордер (`widgets/audio_note.dart`)
  создаются по первому нажатию: в виджет-тестах плагинов нет, созданный при
  сборке плеер уронит тест. `AudioNoteEditor` на экране детали — с ключом по
  коду детали: «Дальше» посреди записи должно её отменить, а не отправить
  на соседнюю деталь.
- **Новое обращение к камере, галерее, микрофону и т. п. на iOS — сначала ключ
  `NS*UsageDescription` в `ios/Runner/Info.plist`**, иначе iOS убьёт приложение
  при первом запросе. Минимальная версия iOS — 15.5 (ML Kit): её держат
  `project.pbxproj` и `ios/Podfile`, понижать нельзя.
- **Верификация — не защита на клиенте.** Гейт на `NearbyOrdersScreen` чисто
  клиентский; на экране карты (`AvailableOrdersScreen`, вход спрятан) его нет —
  возвращая вход, верни и гейт. Сервер проверяет её при отклике, только если
  включён `EXECUTOR_VERIFICATION_REQUIRED`.
- **Город осмотра — `Order.cities.first`, а не начало `address`.** Адрес —
  улица и дом без города, и до выбора исполнителя сервер его не отдаёт; строку
  «Химки, ул. Ленина, 5» собирает `Order.fullAddress`. Подсказки адреса
  (`AddressRepository`) не бросают: пустой ответ — обычное поле.
- **Лента «Заказы рядом» фильтруется и листается сервером**: фильтр уходит
  параметрами (`NearbyFilter.toQuery`), числа «свободные · N» и счётчик шторки
  — из ответа (`availableAll`, `/orders/available/count`), варианты городов и
  марок — фасеты сервера. Не фильтруй загруженный список на клиенте: это
  одна страница. `applyNearbyFilter` живёт только для `MockOrderRepository`.
  `NearbyWhen.apiValue`/`NearbySort.apiValue` — зеркала `AvailableOrders` на
  бекенде.
- **VIN снимает исполнитель — только через `VinCapture`** (`widgets/vin_capture.dart`):
  снимок таблички обязателен, текст распознаёт ML Kit, правится руками. Он
  нужен и кандидату подбора (`StartInspectionScreen` → `addCar`), и старту
  разового осмотра (`CarVinScreen` → `startInspection(vin:)`), одной формой
  через `ApiClient.multipart`. VIN заказчика исполнителю не подставляй — иначе его не сверят
  с машиной. `VinKind` — зеркало `App\Enums\VinKind`. Фото таблички —
  подписанная ссылка `vinPhotoUrl`, Bearer не нужен.
  Снимает своя камера с рамкой (`VinCameraScreen`, плагин `camera`):
  распознаётся вырезка рамки (`recognizeTextInFrame`, пусто — весь кадр), а на
  сервер уходит полный кадр. Пересчёт рамки экрана в кадр — только
  `frameInImage` (`widgets/vin_frame.dart`): превью растянуто по
  `BoxFit.cover`. Камера создаётся только на этом экране — в виджет-тестах
  плагина нет. После снимка всегда шторка сверки «Всё верно»: догадку
  (`guessVin`) показывай как неуверенную, номер не принимай без проверки
  формата.
- **Пробег по одометру — `OdometerCapture`** (`widgets/odometer_capture.dart`)
  рядом с `VinCapture`, на тех же двух экранах: цифры руками, фото приборки
  обязательно, уходит тем же multipart (`CapturedOdometer`). Пробег заказчика
  исполнителю не показывай. `mileageKm` машины — одометр,
  `customerMileageKm` — со слов продавца; плашку расхождения рисуй только по
  `mileageMismatch` с сервера, порог на клиенте не считай.
- **Готовые отчёты по VIN — только из ответа сервера.** Предложение в форме
  осмотра (`VinReportOffer`) рисуется по `checkVinReports`, купленное — по
  `VinReportPurchase`; не считай на клиенте, что подходит и сколько стоит.
  Проверка тратит лимит (15 VIN в сутки) — зови её только по готовому VIN с
  задержкой, как `NewInspectionScreen._onVinChanged`. Отчёт из пакета —
  `InspectionReportScreen.purchased`: заказа у покупателя нет.
- **После вердикта отчёт заморожен** (сервер: 403 на любую правку). Завершённый
  осмотр открывается только экраном «Отчёт» — у кандидата подбора
  `InspectionReportScreen.candidate` (`openCandidateReport`) и у заказчика, и
  у исполнителя; у разового осмотра — «Полный отчёт». Рабочая схема
  (`InspectionOverviewScreen`) — только для идущего осмотра. Не возвращай
  «Поправить отчёт» и второй экран отчёта не заводи.
- **Можно ли откликнуться — `Order.canViewerRespond`**, подпись кнопки —
  `Order.respondLabel`, «Ваш отклик» — `hasViewerResponse` (отклик в игре).
  Только в ленте исполнителя: сервер отдаёт ему лишь его отклик. Второй отклик
  сервер отклонит с 422, кроме устаревшего после переноса даты (`outdated`) —
  он оживает той же записью. Не проверяй `responses.isNotEmpty`.
  После отклика `OrderStore` подменяет заказ в ленте ответом сервера, а не
  убирает его.

## Чего в API нет

Кадр 03 `car-storefront-modes.html` рисует то, чего бекенд не отдаёт, и это
заменено, а не реализовано:

- гонорар заказа — `orders.price` заполняется только при принятии отклика, у
  свободного заказа он `null`. Исполнителю сервер отдаёт в `responses` только
  его собственный отклик, поэтому в ленте — «Ваш отклик» либо «предлагаете вы».
  Число откликов — **только `Order.responsesCount`** (`responses_count`), не
  `responses.length`: у исполнителя там максимум один;
- расстояние «Химки · 8 км» — только у осмотра: точка заказа (`Order.lat/lon`,
  чужим огрублена до ~1 км) против `CityLocator.position()`; у подбора координат
  нет, там — `cities.first`;
- фильтры «До 10 км» и «От 12 000 ₽» не перенесены: работают только «Все · N» и
  «Мало откликов» (`responsesCount <= 2`);
- кнопка «Показать на карте» спрятана: настоящей карты нет.

Понятия «режим» в приложении нет — `mode-switch` из макета не переносился.

## Темы

- Цвета — **только** через `context.colors.*`, стили текста — через
  `context.text.*`. Никаких `Color(0x…)` и `Colors.white/black` в экранах: новый
  цвет — новый токен в обеих палитрах `lib/theme/app_colors.dart`.
- Проверяй вёрстку в обеих темах: `withValues(alpha:)` от акцента, подобранный на
  тёмном фоне, на светлом часто читается иначе.
- Встроенные виджеты Material (выбор даты и времени, диалоги, меню вставки)
  берут цвета из `ColorScheme` и `*PickerTheme` в `AppTheme` — схема
  заполнена целиком. Незаданный тон Material выведет из своего фиолетового
  сида; защищает `test/localization_test.dart`.
- Язык закреплён русским: локаль и делегаты — только в
  `lib/l10n/app_locale.dart`. Тест, проверяющий тексты системных виджетов,
  подключает их же.
- **Не создавай стор в `builder` у `MaterialPageRoute`.** При смене темы builder
  вызывается заново, и экран молча получает новый пустой стор.
